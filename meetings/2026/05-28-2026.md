### Notes
Consolidated autonomy stack for different morphologies


Sensor streams -> Perception -> Planning -> Navigation

Lidar, Radar, Vision, IMU

Factor Graph based Multimodal SLAM -> VLM based scene understanding

Graph based collision aware target planning -> graph based informative planning and exploration behaviour -> Inspection behaviour

Neural MPC OR RL based navigation policies


Hardware stack
Lidar - Robosense Airy
Nvidia Orin NX
IMX 296 Cameras
IMUs

FMCW Radars doppler factor

Q&A: 

Mayank: Is any profiling done on the whole stack?
A: not in particular, but capable of running on very diff compute stacks, only the VLM on GPU

Mayank: Any work for the explainability/verifiability of DL components? 
A: NMPC uses NN mainly for compression of inputs post depth camera first layers, rest is regular MPC, very verifiable. DeepRL stuff - not verifiable.

Alexis
Jacopo: IMU from autopilot? External IMU? 
A: External IMU

Jacopo: MAVROS acceleration control ? Feed anything to state estimator of autopilot? 
A: Yes SLAM output goes as a pose update to EKF

Jacopo: ROS2 dev branch? 
A: Nikhil main developer best to contact

Jacopo: Inter-robot communication? 
A: All to the ground station right now in all current tests.

But more work happening on Collaborative Aerial Ground Marsupial Robots

Compressing point clouds through an encoder to share over the network

https://arxiv.org/abs/2509.07655
https://github.com/ntnu-arl/pcl-vae

Jacopo: Simulation - Gazebo, trying how much GPU/CUDA compute? 
A: Training of learning methods - Aerial Gym for learning
For full stack simulation - Gazebo, multiple reasons, good out of the box physics for different kinds of robots, haven't faced big compute challenges, decent good enough fidelity simulations.

Also exploring other simulation tools for photorealism/massive parallelism

Very extensive statistical testing - won't use Gazebo. Isaac Lab, multirotor classes

Mayank: Which parts break between morphologies
A: SLAM/VLM works as is, navigation varies
PX4/Ardupilot, backend handled, common user interface

Hacks here and there: Robot bringup
Bit complex, different config files, redundancies, param loading

MIMOSA + GBPlanner - in process of migration

Alexis: Mismatch with timestamps, ROS1, ROS2, time sync issue? 
A: Sensor - MCU takes the timestamps from IMU, triggers/correts other sensors, camera, radar. Lidar - PTP sync, correct timestamps

As sharing across ROS1/ROS2 - not sharing large bandwidth data across domains. Full pointcloud never shared across the interface, timestamps in header

Simulation - All on Gazebo clock
